## HyperClipFix 隐私与数据保护政策

生效日期：2026 年 09 月 21 日
最近修订：2026 年 11 月 24 日

HyperClipFix 项目高度尊重并重视用户的个人隐私与数据安全。本软件遵循本地优先、数据最小化与高度透明的技术原则。本《隐私与数据保护政策》（以下简称 “本政策”）详细阐明了本软件在运行过程中涉及的数据处理方式、系统权限使用目的以及用户的权利控制。

### 一、基本数据处理原则与本地存储架构

1.1 纯本地运行架构：维护团队未设立、未运营任何用于收集、汇聚或回传用户设备指纹、身份识别码或操作行为数据的中心化服务器。部分功能会读取第三方公开服务，具体见第二条。
1.2 配置偏好信息：你在应用内配置的所有开关、作用域设置等，均仅保存于 Android 系统分配给本软件的本地私有沙盒存储区（Shared Preferences 目录），不会通过后台私自上传至远程服务器。
1.3 剪贴板数据声明：本模块仅在设备本地放行第三方输入法读取**系统剪贴板历史**，并处理剪贴板显示与权限放行相关逻辑。为实现分组、去重、数量限制与跨设备条目展示，模块可能在本机临时处理必要的条目元数据，例如条目类型、时间、来源标识与文件大小等；本模块不会主动上传、回传或保存剪贴板文本内容，也不会将剪贴内容发送给维护者或第三方服务。剪贴板数据全程由系统本身管理。

### 二、外部网络交互与数据传输场景的充分披露

本软件的核心 Hook 修复逻辑完全在离线状态下运行。仅在以下功能被使用时，软件才会发起受限的网络通信；相关请求不上传你的剪贴板内容、账号凭证或本地文件。

2.1 模块软件版本更新检测与安装包下载
当你在 “关于” 界面主动点击 “检查更新”，或开启了启动应用时自动检查最新版本选项时触发；在你确认下载更新后，客户端会向 GitHub API 查询最新发布信息，并通过 GitHub 发布资源接口下载安装包。更新包下载完成后，可能在你确认后执行安装与相关进程重载。
通信内容限定：客户端向 GitHub API 发起标准 HTTP 查询请求，用于对比版本标签、读取发布说明与定位安装包资源；下载请求会访问 GitHub 发布资源地址或其官方分发节点。请求通常包含网络通信所必需的 HTTP 标头，例如 IP 地址与客户端 User-Agent。

2.2 更新日志读取
当你打开 “关于” 页面中的更新日志，或应用在进入相关页面时预热读取更新日志时，客户端会从 GitHub Releases API 获取公开的版本说明，用于本地展示。

2.3 捐赠名单读取
当你打开捐赠名单，或应用在进入相关页面时预热读取名单时，客户端会访问维护者公开的腾讯文档分享页，读取其中的公开捐赠条目用于本地展示。该页面由腾讯文档独立托管，其可用性与内容不受本软件控制。

隐私边界承诺：上述请求仅包含完成公开信息读取所必需的标准 HTTP 标头；维护团队不会利用上述访问日志对特定用户的真实身份进行画像或行为追踪。

### 三、高级系统权限调用规范与边界限制

为了在 HyperOS 深度定制系统中实现功能配置与权限放行，本软件需在特定场景下申请并使用以下系统权限，其使用边界严格限定如下：
3.1 最高管理员权限（Root 权限）
使用边界：Root 权限仅用于与本模块功能直接相关的本机操作，包括 Root 状态检测、系统日志导出、相关进程重载，以及在你主动确认更新后的新版本静默安装。软件通过执行系统终端命令完成上述操作，不会在后台持续驻留或自动执行更新安装。
安全保证：本软件不会利用 Root 权限扫描你的个人文件、上传账号凭证或私钥、篡改与本模块功能无关的应用数据，或修改与本模块功能无关的系统安全策略，也不会植入特权驻留后门。

3.2 网络通信权限
使用边界：仅用于本政策第二条披露的版本检测、更新日志读取、捐赠名单读取与安装包下载。若你在模块设置中停用更新检测选项，版本检测与更新下载入口将被关闭；更新日志和捐赠名单等公开信息仍可能在进入相关页面或预热读取时发生网络访问。模块的核心剪贴板修复功能不依赖上述网络请求。

### 四、第三方商业 SDK 与分析追踪组件零集成承诺

4.1 商业 SDK 零存在：本软件源代码完全开放透明，内部绝未集成任何第三方商业广告分发 SDK、金融征信组件，亦未集成任何商业化用户行为分析与统计 SDK。
4.2 无数据转让与共享：维护团队不会将使用过程中涉及的任何数据出售、出租、转让或共享给任何商业数据经纪商、广告营销机构或第三方实体。

### 五、用户提交错误日志（Logcat）时的隐私保护指引

5.1 当用户在适配环境中遭遇功能异常并向维护团队提交 Logcat 日志时，请务必注意：Android 系统的原生全局日志缓存可能包含系统正在展示的通知文本、正在运行的应用包名甚至剪贴板片段。
5.2 用户负有在提交日志前进行人工脱敏的法定义务。在将日志发布到 GitHub Issue 或公开社交平台之前，用户必须自行审查日志内容，剔除其中可能涉及的个人姓名、电话号码、真实 IP 地址、账号 Token 及其他敏感个人隐私数据。

### 六、用户对个人数据的完全控制与销毁机制

6.1 离线降级选择权：用户可随时在应用设置内关闭版本更新检测，以减少外部网络连接。关闭该项后，模块仍可离线使用核心剪贴板修复功能；但更新日志、捐赠名单等公开信息在进入相关页面或预热读取时仍可能发生网络访问。如需完全阻断本软件联网，可通过系统网络管理或防火墙策略限制其网络权限。
6.2 数据彻底销毁权：用户可随时通过系统设置内的 “清除存储空间与缓存” 选项，清空本软件在设备本地沙盒中保存的所有偏好设置。用户卸载本软件后，本软件在设备内部创建的所有配置数据将立即被操作系统彻底物理销毁。

### 七、隐私政策的修订与联络

7.1 随着 HyperOS 系统的更新迭代或本软件功能完善，维护团队可能会适时对本政策进行局部修订。修订后的隐私政策将在随附版本的发布说明中向用户公示。
7.2 若你对本政策内容、数据处理逻辑或权限使用存在任何疑问、意见或监督诉求，可通过本软件在 GitHub 的官方开源仓库提交带有 Privacy 标签的 Issue 进行反馈与沟通。
